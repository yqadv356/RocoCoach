# 教练怎样查回合和重放另一招

更新于2026年10月31日。工具让模型查事实和执行有限操作，避免只凭聊天文字推测战斗结果。

## 当前整局工具

| 工具 | 什么时候用 | 实际做什么 |
| --- | --- | --- |
| observe_public_state | 局中和赛后 | 读取允许公开的局面；局中由程序固定读取 |
| inspect_match | 赛后 | 查看整局赛果、行动和理由 |
| inspect_round | 赛后 | 查看某个已发生回合的前后状态与计算 |
| find_key_turns | 赛后 | 按终局、状态和生命变化选最多三个回看候选 |
| simulate_round_alternative | 赛后 | 换成另一合法行动，用引擎独立重放一个回合 |
| search_rules | 赛后 | 检索有来源和版本的规则资料 |
| recall_learning | 赛后 | 读取明确学习记录 |

这是当前整局环境的七项工具，不和旧单回合工具数量相加。读到关键回合只代表值得回看，不代表算法已判定它是失误。

## 以第二回合换招为例

玩家问“第二回合改成撞击会怎样”。模型先查真实回合和可用行动，再请求替代行动工具。程序检查：对局是否结束，第二回合是否存在，行动是否合法且和原行动不同。检查通过才调用引擎。

引擎从该回合之前的历史、种子和规则版本执行一回合，返回实际与分支的剩余生命、状态和差值，主局不变。模型依据这次实际结果解释，不能没有调用却声称已经模拟。

不存在的回合、无效行动和局中请求都会被拒绝。参数用严格类型校验，不接受多余字段。重放子进程最多20秒，剩余预算不足21秒时不启动，已缓存的同请求结果不重复计算。

## “这次回答核对了什么”展示什么

工具回执记录名称、参数、阶段、输入输出哈希、耗时和主局未改变标记。哈希是记录指纹，便于核对同一输入输出，不是回答正确的证明。

每条回答绑定自己实际执行的工具；普通闲聊没调用工具时，不拿上一条复盘的凭据来充数。完整参数可以本机导出，不展示模型隐藏思考。

相关代码：[match_tools.py](../rococoach/match_tools.py)、[MatchEnvironment](../rococoach/match_coach.py)、[agent.py](../rococoach/agent.py)。

## 重放能回答到哪一步

它只回答这个固定种子下一回合会怎样，不计算所有随机结果，也不推演整局胜负。换招可能改变随机数消耗，因此不能当严格控制所有其他事件的因果实验。剩余生命差不是胜率提升，也不一定只来自招式直接伤害。

关键回合选择和进阶策略都是可解释的简化规则，尚无完整策略价值模型。测试检查实际执行、非法请求拒绝和原局不变；语言解释仍需独立检查，见[验证说明](VALIDATION.md)。
