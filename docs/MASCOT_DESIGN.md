# 洛洛像素教练预览版

2026年10月30日。原创笔记精灵：淡紫色身体、金色星点与围巾、薄荷色脸颊、随身笔记本。使用本地代码绘制SVG像素格与CSS轻动画，没有复制Codex内置宠物素材，没有调用图像生成或增加模型请求。它是RocoCoach网页中的教练表现层，未接通Codex桌面悬浮宠物或新增情绪模型。

## 四种可解释状态

| 状态 | 真实来源 | 表现与边界 |
| --- | --- | --- |
| 待机 | 当前没有前台生成活动 | 轻微呼吸与眨眼，不催促、不因输赢惩罚玩家 |
| 查证 | planning、model_start、tool、revision、validating | 看笔记；模型开始不意味着已经有可展示解释 |
| 讲解 | 实际收到非空draft正文 | 小幅说话动作；不把草稿当作已核验答案 |
| 完成 | 宿主保存提示/聊天/复盘，或新局/偏好事务成功后 | 点头一次，标签区分“回答已完成”“新一局已就绪”等；流里的完成字样不能触发成功 |

失败回到安静姿态，显示“这次没完成，记录还在”，不庆祝、不删除已经显示的草稿。文字与错误状态仍由原生命周期处理。原来的模型、对战、工具权限和存储契约不变；没有通过宠物增加代打或未授权操作。

## 实现

`rococoach/mascot.py`负责原创像素格、两个表情帧、固定状态映射和展示适配；`LiveOutput`将真实事件转交适配器。重复正文delta不重建相同状态，避免逐字重启动画。完成只能由页面的成功保存路径通知，失败路径显式恢复。顶栏小图标使用同一形象，聊天顶部固定62px，历史和输入框仍分开布局。

后台复盘的工作线程只保留最近事件类型，不碰Streamlit。浏览器核查暴露跨片段修改顶部占位后下一次定时更新会撤掉洛洛的问题：改为独立顶部片段自己读取同一Job状态，始终拥有自己的DOM；正文片段不再跨位置改它。后台复盘存在期间顶部说明复盘活动，聊天气泡保留自身即时进度；复盘完成以已经提交的结果为准，后续普通重绘恢复待机。

设置里的“洛洛动作”为当前会话开关，关闭只停止动画，不改对局或模型。CSS同时尊重系统prefers-reduced-motion，关闭时保留第一帧，不出现双帧叠影。状态有文字和礼貌播报，装饰帧不重复向读屏器播报。未实现跨设备动画偏好保存、声音或复杂情绪系统。

## 核查范围

- 自动化覆盖真实事件映射、空draft、不可由提供商完成事件庆祝、失败恢复、重复delta去重、SVG有效性、文本转义，以及关闭动画不改局面/偏好操作不重开。
- 浏览器使用8502独立临时SQLite、实际引擎和明确标记的模拟模型事件，核查待机→查证→讲解→保存完成、末尾失败保留、后台复盘片段。它证明界面事件链路，不冒充新增真实LLM评测或性能结果。
- 1280×720：左侧clientHeight与scrollHeight均582，输入框底部690；1470×900：左侧均762，输入框底部870。增加宠物未造成左侧滚动或把输入框挤出屏幕。
- 浏览器实际关闭动作后animation-name为none，第二帧opacity为0；开关不增加模型调用。系统减少动态效果规则已实现，尚未在浏览器模拟系统设置。
- `lolo-states-preview.png`只展示四种外观；`lolo-companion-preview.png`、`lolo-checking-preview.png`、`lolo-speaking-preview.png`、`lolo-failure-preview.png`来自隔离模拟链路。不会据此声称真实玩家觉得更有趣或学习效果提升。

此版是可试用的轻量表现层。当前设计说明书已纳入像素伙伴的事件设计与界面验证，并清楚标记截图使用模拟模型事件；不把未验证的陪伴效果写成既定成果。当前完整结果见[验证说明](VALIDATION.md)。
