# 终局即时展示、后台复盘与稳定文本

2026-10-30，修复用户反馈“生成了一大段后消失、只剩术语提示、结束时卡住”。

## 实际根因

1. 旧zh.dialogue检测到任意两个连续拉丁字母，就将整段回复替换成“未转换的术语”。检查真实保存的本局复盘和追问，未翻译片段来自玩家英文昵称；原始文字仍在SQLite，数据没丢。这是展示层误杀，不是模型没有回答。流式草稿先走text，完整消息再走dialogue，两个显示路径不一致，导致先看到正文、最终突然变占位。
2. generate_final_review在页面绘制过程中同步调用有限工具Agent。虽然底层provider stream早已存在，但查证前几轮主要返回工具调用，没有正文；主页面要等整段复盘完成才继续，给玩家造成停住的感觉。
3. 预览是临时占位，完成后会清空转入历史。整段过滤和位置切换叠加，看起来像内容被撤回。

## 当前实现

- 显示层只翻译已知词，保留昵称、专名和未知短词，不因少量英文删除整段；不凭空猜未知词翻译。调整词边界，保护带下划线/数字的名称。原机制、证据、合法动作和局中不代选检查仍在业务层。
- review_jobs.py用最多两个工作线程调用已有真实review_match，不接触Streamlit、不替玩家行动。冻结输入副本，任务按局ID+模式复用，页面刷新不会为同一任务再发一套调用。只限制并发线程，并非生产分布式队列。
- 主页面先绘制终局/生命/回放和聊天，再启动后台任务。st.fragment每0.3秒读取线程安全进度快照；模型在查回合时显示实际查证进度，正文到达后逐步展示“复盘草稿”。不是把完整文本拆字伪装流式。
- Future成功后在页面主线程一次提交review、正式聊天与学习事件，再刷新页面。提交按局ID幂等，不重复添加教师消息；最终显示与草稿使用一致的非破坏性中文转换。
- 校验失败需要修订时明确显示“重新整理”，不会把被拒草稿当正式复盘入库。失败仍保留trace，正常赛果与历史不会回滚，人工重试是新任务。离线规则复盘很快，保留同步路径并明确mock来源。
- 页面片段核对局ID防串局。用户提前切换新局后，旧任务可能仍运行；目前需回到旧局并触发页面收集才能落正式复盘，未实现离页可靠持久任务或跨进程作业恢复。服务重启会丢内存任务，已保存赛果仍在；不要把单机原型写成生产任务系统。任务注册表清理已完成旧任务，仅保留近期结果，仍可能暂存多个排队任务。

## 验证

测试验证多个英文昵称/专名仍保留整段、任务阻塞时主页面仍有赛果与下一局按钮、回调可见、同局任务复用、原局不变、结束后正式正文留存、刷新不重复教师和学习记录。完整160项通过42.30秒。

scripts/check_async_review.py不读取私人玩家记录，独立合成practice47并调用真实模型，记录docs/async-review-live-evidence.json：任务分发0.0019秒，首正文16.58秒、72次草稿更新，最终核验20.747秒、372字符可显示，没有被占位替换。这是一次开发实测，不是P95或普遍延迟承诺。0.0019秒仅是把任务交给线程，不是模型生成速度；查证16秒等待仍存在，改善的是页面不冻结、进度可见和最终文本不消失。

本轮不重写Agent、不训练模型、不模拟加速；界面流式进度不代表解释内容已全部正确，最终语义仍需审阅。旧错误截图和证据不覆盖，PDF尚未同步。

## 2026-10-30 第二次优化：减少等待并修复片段交接

用户再次报告等待长、正文短暂消失。本次发现仍存在两条路径：自动复盘按通用Agent先询问模型“要读什么”，再读取整局/回合，会耗费多次远程往返；片段完成后调用整页rerun，且已完成分支直接return，会把该片段已有的输出清空或交接到另一个位置。

当前自动复盘改为确定性取证：宿主真实执行inspect_match、find_key_turns、inspect_round（终局及最多一个其他候选）。凭据标注selected_by=host、step=0，不能宣传成模型自主选择。仍以同一权限门控和输入/输出哈希核验，不改对局。证据齐全后直接请求结构化总结，常规只需一次模型调用，最多再做一次格式/引用修正，总预算40秒。首次取证不做反事实模拟；需要深入比较的赛后追问仍使用原有限工具Agent按问题自主选择工具，能力没有伪装进自动总结。

最终总结请求使用provider JSON object响应格式。首轮实测（async-review-prefetch-live-evidence.json）保留失败：未开启JSON模式时模型输出Markdown围栏和未转义引号，导致两轮格式修正失败，不隐瞒为成功，也不增加针对某一句话的替换。补齐JSON输出约束后，第二次真实调用（async-review-prefetch-json-live-evidence.json）：1次模型请求、4个宿主本地工具、首正文1.490秒、96次流式更新、核验10.331秒，正文440字。旧基线一次为首正文16.580秒、核验20.747秒。两次为单个合成样本与不同调用时刻，不能证明P95或普遍加速倍数。

片段完成时：把结果写入当前session中的match（显式传入，不依赖可能旧的全局game闭包），幂等保存正式聊天和学习记录；在同一个片段位置渲染正式复盘，不再整页rerun。后续定时回调也渲染完成内容，不能空return。正常整页重绘则从已保存消息显示同一份正文与下一局目标，片段不再挂载，避免重复。错误也有稳定占位和片段内重试按钮。普通补充工具进度不清空已有草稿；被校验拒绝的草稿仍撤下并明确显示重新整理，不能把不合格内容永久保留。

赛果、回合记录和下一局操作继续先呈现；等待首正文时显示根据实际记录生成的赛果/回合数，并明确仍在整理复盘，不冒充模型输出。当前等待中的片段每0.3秒更新，完成后在该页面停留期间仍会定时重绘其完成内容，直到下一次正常整页操作；未实现浏览器端持久组件或服务重启恢复。提前离开旧局的任务落盘限制仍与前文相同。

浏览器隔离夹具（8502根入口，独立SQLite、假模型配置、固定延迟模拟流）验证不操作玩家现有对局：自动完成后多次定时更新仍有同一复盘，下一局目标可见；保存review-stable-fragment-preview.png。这张截图证明页面生命周期，不证明真实模型速度；速度取自独立真实调用证据。完整回归见BUILD_LOG第33节。

真实输出的语义仍需审阅：本次成功样例有对未详细读取的回合做扩展解释、以最高直接伤害评分表扬固定选招、伤害预测口吻与局中信息边界不够严谨等问题。工程优化和格式正确不等于解释准确率通过，原文保留供后续评估；未对个别句子做定制修补。

## 普通聊天的不同失败分支

第35轮重新确认：普通聊天仍存在“显示草稿→末尾校验失败→reject清空→固定基础观察→rerun”分支，不能用本文的自动复盘成功验证替代。现按请求保存生成/完成/失败状态与可见草稿，正常聊天原位收尾，失败内容标记可查但排除后续上下文；后台复盘也补充修订草稿保留。详情与旧测试验收缺陷见RESPONSE_LIFECYCLE.md。后续最终完整193项通过64.03秒；保留前文历史成绩，不将其解释为已覆盖所有路径。
