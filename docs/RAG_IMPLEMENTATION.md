# RAG怎样让规则回答有出处

更新于2026年10月31日。这里的RAG就是：先找资料，再让模型结合资料回答。当前是26条资料的小型词法检索，没有向量数据库。

## 为什么需要它

模型可能记错招式、混淆版本，或者把别的游戏机制当成本局规则。仅要求“不要编造”不够，回答规则问题时应提供实际来源。

RAG负责找规则，不负责读取当前血量、天气或特性。这些当前状态必须从对局工具拿，不能用一般物种资料猜。

## 资料从哪里来

| 内容 | 数量 | 来源 |
| --- | --- | --- |
| 原型原则 | 4 | 项目自己的教学和比较规则，明确标为原型原则 |
| 招式资料 | 17 | 固定Showdown 0.11.11 Dex |
| 物种资料 | 5 | 同一Dex的属性与可能特性 |

[export_knowledge.cjs](../engine/export_knowledge.cjs)读取已安装引擎，[build_knowledge.py](../scripts/build_knowledge.py)生成[语料](../data/rag_corpus.json)。中文名称沿用已有名称表，原机制描述保留。

每条资料记录来源位置、包版本和内容哈希；整库也有哈希。哈希相当于内容指纹，便于发现变化，不代表资料一定正确。加载时会检查内容、重复编号、范围和版本，异常就明确失败。

## 一个问题怎样找到资料

以“电光一闪为什么先出手”为例：赛后模型发起规则查询，检索器识别名称和查询词，从资料中找相关条目，返回前两条及来源，再交给模型解释。最后检查回答引用的编号是否确实读过。

检索在[retrieval.py](../rococoach/retrieval.py)中完成：中文拆相邻双字片段、英文拆词；补充明确别名，比如“打不准”和“命中”；使用BM25形式的词法评分，再按实体和覆盖范围筛选。参数为k1=1.2、b=0.75。

记录会保留原查询、扩展词、候选分项分数、入选条目和语料版本。分数用于排序，不是“答案正确的概率”。没有训练语义模型，也没有运行Lucene；公式参数参考[Lucene官方说明](https://lucene.apache.org/core/9_12_3/core/org/apache/lucene/search/similarities/BM25Similarity.html)。

## 找不到怎么办

明确不在资料范围的招式、其他游戏机制、活动或兑换码，不拿相似条目凑答案。程序会给范围说明，并在记录中标明这是程序处理，不伪称模型查到了规则。一般查询没命中时，仍可在预算内调整检索词。

这种范围判断偏保守，复杂混合问题仍可能漏判或多拒。资料引用有效也不等于解释完全正确，RAG没有消除所有错误。

## 有没有证明检索变好了

用相同20个人工问题比较，16题可答、4题超出范围：

| 方法 | 可答题Hit@2 | 越界题返回空 |
| --- | --- | --- |
| 4条资料与原关键词 | 5/16 | 2/4 |
| 26条资料与原关键词 | 12/16 | 2/4 |
| 新检索首次对应版本 | 15/16 | 4/4 |
| 修正后同题回归 | 16/16 | 4/4 |

Hit@2只表示前两条里包含预先标注的相关资料，不是最终回答正确率。扩大资料本身已经带来提升，不能把全部收益归给BM25。

首次检查把“为什么不能只看面板威力”误当成未知实体。修正后继续测同一批题，就只能称回归，不能再称独立留出成绩。首次失败和后续结果分别保留在[首次报告](rag-evaluation.json)与[回归报告](rag-evaluation-final.json)。

下一步先补独立问题和可靠资料，再看词法检索漏掉哪些问题，决定是否需要向量或混合检索。当前不凭小库回归成绩宣称线上准确率或教学收益。其他验证口径见[VALIDATION](VALIDATION.md)。
