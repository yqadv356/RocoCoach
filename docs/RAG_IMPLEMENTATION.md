# RAG v2：覆盖、排序、版本与评测

更新时间：2026-10-29。当前为26条资料的本地词法RAG，已接入工具Agent；没有embedding、向量数据库或模型重排。旧版4条关键词基线及真实证据保留，不能把历史记录改写成新版本结果。

## 1. 这一轮为什么改

原版只统计4条人工说明的关键词，遇到“打不准”等口语容易漏检，也无法回答具体招式资料。日志没有候选分数和知识版本，面试时难以说明命中原因。优化优先解决资料覆盖、可追溯检索和未覆盖范围控制，保持前台统一输入。

## 2. 资料从哪里来

| 内容 | 数量 | 来源与边界 |
| --- | --- | --- |
| 原型原则 | 4 | 保留原data/coach_knowledge.json，区分本项目比较启发式、实际机制和学习评估 |
| 招式资料 | 17 | 从本地固定pokemon-showdown 0.11.11 Dex导出，含属性、分类、威力、标称命中、优先度与英文原始描述 |
| 物种资料 | 5 | 同一Dex的物种属性与可能特性；物种信息不等于当前对局能力或已装备特性 |

engine/export_knowledge.cjs读取已安装包；scripts/build_knowledge.py生成data/rag_corpus.json。来源版本不符则要求复核，未联网抓攻略或导入洛克王国真实资料。中文名沿用已有PokeAPI名称表；原始机制文本保留，不能将模型翻译当成新的权威来源。

每条保留来源定位、来源版本、内容SHA-256；整个语料有corpus_hash。内容一致的重建不覆盖文件；不同内容需另存或显式replace。检索重新校验内容、范围、重复ID和版本；不合格时工具明确失败，不偷偷读旧资料。来源日期和版本不意味着已验证所有自然语言解释。

当前语料哈希、构建脚本与原始事实都在项目内，可离线重建。不把当前26条称为大型游戏知识库。

## 3. 检索如何工作

问题 → Agent按需生成检索词 → 显式口语扩展 → 词法评分与实体/范围筛选 → Top-2 → 工具观察回传模型 → 引用检查或范围说明。

rococoach/retrieval.py：

1. 中文使用相邻双字片段，英文使用词；显式别名扩展“打不中/打不准/空招”“先出手”“STAB”等。不是训练出的语义模型。
2. 使用BM25形式的词频/逆文档频率与长度归一化，k1=1.2、b=0.75。另加明确的实体命中和原则卡片权重；分项分数进入日志。
3. 具体招式/宠物名称优先自己的资料，中文和英文名称均支持；单字招式“抓”也有回归测试。
4. 缺少覆盖锚点时不因“机制”等共有词随便返回别的招式。明确询问其他游戏、未索引实体或活动/兑换码，返回范围原因。
5. 日志保留原查询、扩展词、算法版本、参数、前5候选分项分数、入选条目/来源/哈希、语料哈希与别名表哈希。分数是排序分值，不是答案置信概率。

BM25公式参数参考[Lucene BM25Similarity官方说明](https://lucene.apache.org/core/9_12_3/core/org/apache/lucene/search/similarities/BM25Similarity.html)。这是独立的小型实现，未运行Lucene，也不宣称它与Lucene的分词或分数完全一致。

## 4. 未覆盖时如何处理

命中文档以实际证据ID返回。没命中则规则证据为空；另有retrieval:coverage记录本次未覆盖的原因和语料版本，它不是游戏机制文档。

明确越界、显式未收录实体、活动/兑换码请求，聊天流程由宿主生成中文范围说明并提前停止，stop_reason=coverage_abstention、answer_source=coverage_policy。不把宿主拒答包装成模型推理，也不让模型用另一招资料回答未知招式。一般词语未命中仍允许在预算内调整查询。

这类识别偏保守，混合问题、复杂省略和同义表达仍可能漏检或过度拒答。引用确实存在也不等于完整语义蕴含；不能说RAG消除了幻觉。

## 5. 固定回归集与对照

数据：data/rag_eval.json，20个人工合成问题，其中开发12题、最初留出8题；总计16个可答、4个未覆盖问题。不是线上分布或独立外部标注。Hit@2仅表示前两条至少包含一条预先标注的相关证据，不是最终回答准确率；标签也不是穷尽的相关性判断。

| 方法 | 16个可答问题命中 | 4个未覆盖问题正确返回空 |
| --- | --- | --- |
| 原4条 + 原关键词 | 5/16 | 2/4 |
| 新26条 + 原关键词 | 12/16 | 2/4 |
| 新检索首次留出检查对应版本 | 15/16 | 4/4 |
| 修正失败后的回归重测 | 16/16 | 4/4 |

首次未用于调参的8题检查：6个可答命中5个，2个未覆盖均为空。“为什么不能只看面板威力”被错误解析成未收录实体；保留rag-evaluation.json。修正概念问句判定后，该组已被用于修正，因此后续6/6只能叫回归重测，不能再叫独立留出成绩。rag-evaluation-refined.json与rag-evaluation-final.json继续保留，不覆盖首次结果。

三组对照区分了语料扩展与整套检索策略的收益；没有将全部收益归于BM25单项。没有做embedding对照、在线用户实验或检索成功→教学收益的因果验证。

## 6. 真实千问集成

rag-live-evidence.json保存三个合成真实调用：

- 电光一闪：实际检索优先度资料并解释，6.914秒。
- 打雷天气：检索原始机制说明，明确没有查询当前天气，3.800秒。
- 地震威力：检索确认未收录后由范围策略说明，0.967秒；不是编造数值或模型自主事实结论。

记录包括工具查询、候选分数、扩展词、实际命中、最终引用、版本与用量。这些时长是整个请求，不是纯检索耗时。历史agent-live-evidence.json仍保留原4条知识阶段的真实检索例子。

## 7. 失败统计与界面细节

AgentFailure现在保存已完成请求数、已返回token、工具调用、用时、停止原因和部分轨迹。失败/未返回的API账单可能未知，不能把已返回用量当完整费用。

当前局面工具补充双方属性和当前能力，避免把物种资料替代当前状态。新复盘的查证记录覆盖更早的聊天展示；分支核验以小字保留精确数据，减少大段重复。不增加角色、检索或调参按钮。

## 8. 面试说法

“我从4条关键词基线扩到26条有固定来源和哈希的资料，实现BM25、显式同义词、实体与范围策略。用相同问题比较原语料、扩展语料和新检索，保留首次失败与修正后的重测。检索轨迹可核对，但仍是小型词法RAG，没有向量库，也不把回归集命中当作回答准确率或学习效果。”

后续优先补充可授权、版本明确的资料与独立问题集，测复杂混合意图和未收录机制；只有词法召回的失败证据充分时再比较语义或混合方案。以上为后续范围，尚未实现。
