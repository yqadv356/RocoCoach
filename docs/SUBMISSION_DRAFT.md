# RocoCoach 基于 LLM 的智能陪练教练

面试提交稿　2026年10月31日　当前实现与验证说明

## 一 交付摘要与题目对齐

RocoCoach 把一场宠物对战变成可解释的练习过程：玩家自主出招，洛洛在回合前引导观察，赛后依据实际记录解释关键选择，再给下一局可练习的目标。军师、陪练和老师使用同一个聊天入口，由场景和问题决定回应侧重。

三天原型优先完成老师的流程闭环，已交付整局 Demo、真实千问调用、受限工具 Agent、可追溯 RAG、上下文与偏好、对话操作和消息恢复。当前证明了流程可运行，尚未通过真实玩家实验证明学习效果、胜率或留存提升。

| 题目角色 | 当前实现 | 验收边界 |
| --- | --- | --- |
| 老师 | 回合前引导、自主决策、整局复盘、下一局训练目标 | 完整教学流程；尚无长期掌握度或迁移效果证明 |
| 军师 | 公开因素解释，赛后查证回合、规则和单回合替代行动 | 不代打、不在局中排名；未实现完整阵容规划 |
| 陪练 | 统一聊天、近期对话、显式偏好、学习事件、原创像素伙伴 | 有跨请求状态；情绪与关系质量未独立评测 |

没有真实游戏接口时，复用 Pokémon Showdown 0.11.11 结算、Smogon calc 0.12.0 计算，提供四个固定教学场景。原型面向宠物对战玩法，不代表《洛克王国》的实际机制或官方接口。

当前代码仓库为 https://github.com/yqadv356/RocoCoach 。公开源码、Word、PDF 与运行说明已提交；云端发布基线通过 227 项自动化测试。本文中的真实调用、小规模探索和程序回归分开说明，不合并成一个准确率。

## 二 玩家流程与交互设计

### 从练习到下一次改进

玩家查看生命、属性和剩余次数，洛洛提示命中风险、属性关系等观察维度；玩家自主选招，也可写一句理由。聊天不推进回合。引擎保存行动前后快照、理由与真实事件，终局立即展示赛果、后台生成复盘。

赛后可追问某回合、独立重放另一招，再得到一个可观察的下局目标，例如出招前说明落空后果。当前完成练习与反馈流程，尚未自动测量掌握度；独立小测页面不混称自适应课程。

### 统一入口与公平边界

玩家不必切换角色按钮。局中只用公开观察、不显示逐招排名，赛后才开放细算与分支。左侧对战、右侧聊天，输入框留在视口内，详细规则和凭据按需展开，调试信息不占主要操作区域。

### 原创像素洛洛

原创笔记精灵按真实事件呈现待机、查证、讲解、完成。收到正文才讲解，保存成功才完成；失败保留草稿。动画可关闭，支持减少动态效果，不增加模型调用。它未复制 Codex 宠物素材或接通桌面宠物 API，尚无陪伴效果实验。

## 三 架构与一次请求的数据流

| 层次 | 组件 | 职责 |
| --- | --- | --- |
| 交互 | Streamlit 与 LiveOutput | 对战操作、流式正文、请求状态、刷新恢复 |
| 理解 | 千问与结构化 IntentPlan | 结合语境理解问题、指代、操作和风格 |
| 调度 | 语义计划与有限工具循环 | 区分轻量回应、受限写操作和赛后查证 |
| 事实 | 引擎、计算器、版本化 RAG | 提供实际结算、伤害范围和规则资料 |
| 状态 | 整局账本与 SQLite | 保存快照、理由、消息、偏好、学习事件和回执 |
| 约束 | 参数、阶段、操作结果检查与事务 | 拒绝非法能力、过期状态和重复提交 |

### 同一个入口的三条执行路径

普通聊天：读取当前问题、受限局面与近期完成对话，生成对应风格的回复；内容按提供商真实流输出，完成后保存。

赛后查证：模型在预算内选择工具和参数，应用程序执行并返回观察，模型再决定继续查证或回答。回答携带证据引用，玩家可展开实际工具记录。

对话操作：模型提出字段和参数明确的计划，应用程序核验参数和当前状态，准备候选结果、检查实际效果，再以事务保存并反馈。计划本身不改变对局，也不能证明操作已完成。

Python 管教练、界面和状态，Node 桥接固定版本引擎。模型负责理解语言与解释，程序掌握规则计算和写入权限。未来替换真实游戏适配器仍需授权、机制版本、合法行动接口及重新评测，不能只换宠物名称。

### 可解释性具体展示什么

公开的是实际工具、参数、结果摘要、规则来源、版本与回执，不是模型的隐藏思考。对局事实、规则资料和模型推测分别处理；引用存在或哈希一致只证明可核对的记录，不证明所有自然语言结论成立。

## 四 智能体如何可靠执行

### 语义计划与受限能力

在线人工消息统一生成严格 IntentPlan，读取当前阶段、场景、档位、近期完成对话、最新助手提议和有效待办。在线操作不依赖“好的”“难一点”等专用短语列表；离线规则演示单独保留。

写能力只有 start_new_match 和 set_response_style，参数限于现有场景、两档对手与三种表达风格。模型不能写任意档案、SQL 或代码，也不能通过聊天工具替玩家出招。简单写操作采用结构化计划与应用程序执行，复杂赛后查证才使用原生 Function Calling，二者不混称。

### 从确认到提交

新提议保存待办 ID、精确参数、来源状态和五分钟期限。玩家当前明确接受且指代仍有效时才能执行；过期、串话、状态改变或方案替换则不执行。替换未结束整局还增加语义副作用核对，避免把重讲或再试一次误作重开。

应用程序先创建候选新局，检查新 ID、零回合、未结束、场景、档位和规则版本。随后用请求编号保证同一请求只执行一次，并在一次数据库事务中核对局面、合并新增消息、保留旧局；这次操作要么整体保存，要么失败退出。只有实际保存成功才说新局已开始；模型服务失败不退回关键词自动执行。

### 工具预算与实际观察

赛后原生工具循环最多五次模型请求、八次工具、七十五秒；阶段白名单和严格参数约束每次执行。独立换招只重放一个已发生回合，不修改主局；固定种子样本不能推断胜率。自动复盘由应用程序预取证据再总结，轨迹明确标记应用程序选择，不伪称模型自主选取。

进阶对手按公开状态计算直接伤害区间均值乘标称命中率，替代随机策略；不偷看玩家选择、不修改数值。它未完整评估控制、资源和多回合目标，不能称为最优战术。项目没有 Agentic RL 或多 Agent。

代价是每条在线人工消息多一次规划调用，探索样例约一至三秒；二次语义复核仍可能相关地出错。程序约束控制副作用，不能保证语言理解永远正确。

## 五 RAG 与上下文机制

### 资料和检索路径

知识库共 26 条：4 条原型原则、17 条招式、5 条物种。机制从固定 Showdown Dex 导出，保留来源定位、包版本、每条资料及整库的内容指纹（哈希）。物种可能特性不等于本局已装备特性，资料不能替代当前天气或生命状态。

检索将中文双字片段、英文词与显式别名送入 BM25 形式评分，k1 为 1.2、b 为 0.75，再做实体和覆盖范围筛选，返回前两条。轨迹记录查询、候选分项分数、入选资料和版本。未覆盖时说明范围，不用另一招资料凑答案。当前没有 embedding、向量数据库或模型重排。

| 相同 20 题集的对照 | 可答 Hit@2 | 越界返回空 |
| --- | --- | --- |
| 4 条资料与原关键词 | 5/16 | 2/4 |
| 26 条资料与原关键词 | 12/16 | 2/4 |
| 新检索首次对应版本 | 15/16 | 4/4 |
| 修正后同题回归 | 16/16 | 4/4 |

其中 16 题可答、4 题未覆盖，均为人工合成题。首次检查发现概念问句被误判，修正后同题成绩只能称回归，不能继续称独立留出。Hit@2 不是回答准确率，全部提升也不能只归因于 BM25。

### 分层上下文与记忆

上下文包含当前引擎状态、近期完成对话、明确档案偏好和最近学习摘要。普通近期对话保留六轮，语义规划取五轮，工具 Agent 使用更短窗口；学习摘要取最近五条。SQLite 保存完整整局，模型只取阶段允许的受限视图。

生成中或失败草稿可供用户查看，但不作为后续事实或正常学习成果。已有显式偏好、事件记忆与有界上下文，尚无自动长期人格提炼、Memory Stream 排序或 Reflection 训练。后续应让玩家查看、更正和删除推断，再评估跨局教学价值。

## 六 难点与修复依据

### 流式文字结束后消失

先后定位到三类原因：中文过滤误杀英文昵称；后台复盘完成后整页重绘撤掉占位；普通聊天末尾校验失败后覆盖成固定观察。早期只测成功路径，甚至把失败清空当正确，未覆盖用户看到的完整生命周期。

改为 request_id 绑定同一条生成中消息，每约半秒保存实际可见草稿；成功或失败均更新原消息，普通聊天在原位置完成展示和保存。失败保留可见版本并标记尚未核对，刷新可恢复、不把失败草稿作为后续事实。检查点不是逐字落盘，进程瞬断仍可能丢少量内容。

### 终局复盘等待较长

旧流程串行经过多轮工具决策。改为立即显示赛果，冻结对局快照，在后台预读整局、关键回合及最多两个回合详情，再由模型总结；最多两次生成修正、四十秒预算。单次真实样例首正文 1.490 秒、核验 10.331 秒，仅证明该路径，不外推 P95 或加速倍数。后台线程不是生产任务队列。

### 答应重开却没有执行

根因是短语路由、口头提议与实际动作脱节。改为统一语义计划、结构化待办、操作结果检查和防重复提交，而非添加更多专用回复。真实探索仍出现“再做一次”误分，因此对替换未结束整局增加语义复核并保留失败证据。

### 次数约束与短局不匹配

原引擎长局额度在几回合内几乎无约束。增加版本化短局额度：基础次数除十向上取整，双方一致，实际由引擎扣减；用尽禁用，全耗尽进入挣扎及反伤。旧局保留原规则，推进和分支携带版本。这是自定义教学规则，尚未做正式平衡实验。

### 像素伙伴完成后也会消失

界面核查发现跨片段写顶部占位，在定时更新后被撤销。让顶部片段拥有自己的 DOM、读取同一后台任务状态，正文不跨位置修改它。使用隔离模拟事件验证完成、失败和定时更新；不把界面测试说成新增模型效果。

## 八 交付演示与后续优先级

### 五分钟演示

第一分钟说明老师闭环与规则复用边界，开始均衡训练。随后展示一次回合前引导、自主选招与实际结算，穿插一句聊天，说明它不推进回合。完成整局后先看即时赛果，再看后台复盘及证据；追问一个已发生回合的替代行动，解释它只重放单回合、不会改写主局。最后在聊天中要求进阶训练，检查实际新局与保存回执，并演示表达风格偏好。

网络或模型失败时使用明确标记的历史合成证据，不把截图当实时响应；无密钥规则演示也要说明。现场应能独立解释一次请求的数据流、一个失败修复和一项测试的实际边界。

### 运行与提交

需要 Python 3.12、Node.js 24、pnpm 11，安装锁定依赖后启动 Streamlit。真实 LLM 密钥仅放本地 .env；无密钥可做规则演示。README 提供完整命令，仓库含源码、回归、合成证据、Word/PDF 与第三方许可，排除私人对局和密钥。

三天任务分解为：建立可运行整局与事实接口，完成教练与证据工具，验证失败恢复并整理交付。这是范围安排，不是测得的个人工时。没有为增加术语而接入 RL、向量库或多 Agent。

### 优先改进

先补独立语义与教学质量评审，并测延迟分位数和用量；再据结果决定是否合并规划请求、调整模型或扩大检索。随后验证下一局目标是否迁移到玩家的独立判断。生产化再补多用户认证、可删除记忆、持久任务队列与并发仲裁。

Codex 参与代码、调试和文档；第三方提供结算、计算、名称与部分素材。新增工作是整局教学流程、受限语义动作、证据适配、上下文、消息恢复与验证。候选人需亲自理解和演示这些取舍。
