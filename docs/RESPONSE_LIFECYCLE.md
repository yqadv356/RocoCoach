# 流式文字为什么消失，以及本次完整处理流程

2026-10-30。此文记录第35轮修复；先前ASYNC_REVIEW.md对应的修复仍有价值，但未覆盖这里的普通聊天失败分支。

## 这次查到的证据

用户截图中的“正在生成·尚未核验”来自LiveOutput；“基础观察：这部分先放一放……”来自页面普通聊天的异常处理，不是自动复盘片段。只读检查本机最新对局，找到两条相应chat_failures：每次有限Agent均请求5轮后失败，trace中的最终校验错误为当前场景宠物不一致。模型把新对局诉求当作当前已结束战局的讲解，生成了别的宠物配置；随后又按当前战局的物种范围验证它，反复被拒。具体原文仍保存在玩家本机记录，不复制私人昵称/对话到此文。

“再来个难一点的对局”没有命中原对话操作的窄候选表达，落入赛后讲解。第三次相关请求后来有正式回复保存，不能把每条相似请求都认成同一次失败。旧失败没有request_id/query的完整归属，本次不靠猜测把某个trace移植成历史正式消息。

## 旧流程与之前修复的覆盖范围

旧普通聊天流程：

1. 玩家提交，页面临时画用户气泡与LiveOutput，没有先保存这条请求。
2. SDK收到增量，解析reply字段，尚未通过最终校验的文字立即显示。
3. 完成后执行JSON/schema、证据引用、场景宠物等程序检查；不通过时revision清空正文，再请求模型修正。
4. 达到步骤/时间上限后抛异常，页面view.reject清空正文。
5. 仅把固定“基础观察”写进聊天，保存并整页rerun；原草稿只可能留在失败trace中，用户看不到。

之前两次修复：英文昵称导致dialogue整段过滤，已经改成非破坏翻译；自动复盘后台任务完成后片段空return/整页交接，已改为同片段保留。它们没有修到上述第4/5步。此前成功截图和AppTest能证明相应成功路径，不能证明普通聊天末尾校验失败也不会丢文字。

更关键的测试缺陷：旧test_preview_is_withdrawn_when_revising_or_failing和流式失败页面用例，明确断言草稿被清掉、失败后页面不出现草稿。这是当时将“防止未核验内容成为正式回答”错误地等同于“删除可见草稿”的验收规则，和用户要求相反。之前的187项通过不构成本问题已解决的证据。此次替换验收目标，而非只改提示词或增加一次成功截图。

## 当前状态流程

| 状态 | 展示 | 保存与模型上下文 |
| --- | --- | --- |
| generating | 已展示的增量草稿；核对/修正时保留可见文字和明确状态 | 先写request_id、用户输入、待完成气泡；接收增量时最多每0.5秒保存可见草稿，修订节点也保存 |
| completed | 原位置显示完整正式回复，不自动整页rerun；有过修订时可展开先前草稿 | 同一个气泡更新为completed，写正常聊天事件；仅正式文字进入后续对话上下文 |
| failed | 原位置保留最后已展示文字，明确未完成/未通过核对；有多版可立即展开 | 同一个气泡更新为chat_failed，保存草稿、query/request_id和诊断；不写成正常学习/聊天事实 |
| 刷新后 | 从SQLite恢复正式回答或失败草稿；失败草稿默认可展开查看 | session.dialogue_history跳过generating/failed，不把错误草稿喂回模型 |

每次只记录已经实际画出的正文（不是把完整rejected_output偷偷展示出来）。最多保留8版、每版12000字符，覆盖目前最多5轮的Agent；不记录或展示模型隐藏思考。草稿是可检查的生成产物，不能等同于事实、已执行操作或正式教练建议。局中未被输出的违规招式答案不会通过诊断字段重新泄露到界面。

普通聊天现在成功与失败都在原气泡收尾并保存，取消自动整页重绘；下次正常交互从消息账本重建。离线回答同样直接展示工具凭据，避免取消rerun后证据要等下次刷新才出现。开新局等真实界面切换仍需要rerun，其事务会移除当前pending占位，并原子写入一次用户请求和真实执行反馈，避免重复用户气泡/悬挂生成状态。

自动复盘还补充了同类失败保护：ReviewJob记录修订草稿，失败后存review_previews；错误片段和刷新后的重试位置仍可查看。完成的复盘可以查看被替换的草稿，但只用正式answer进行学习记录与复盘事实引用。

## 新对局意图与能力边界

候选识别从窄的“再来一局”扩为动词+对局/局/次等表达；解释/重放类请求仍走原问答，不作为重开授权。参数白名单、当前消息授权、并发检查继续保留。请求改变难度但未明确场景时，工具不允许用same偷偷重开，也不能虚构一套新对手。

当前没有经过验证的难度分级，不应宣称随机换个对手就是更难。inspect_session现提供真实四个场景及此能力边界。difficulty-intent-live-evidence.json为独立合成局的真实千问调用：3.345秒，正确说明尚无难度分级、提供现有场景，command为空，没有编造开局。此为一例，非所有中文意图的准确率评估。

## 验证方式

- 普通聊天流式后模拟连接中断：失败正文仍可见，刷新后还在；只把已完成回复写正常chat事件。
- 先显示第一版、修订后显示第二版、最后抛AgentFailure：验证两版都能恢复，request_id/query关联完整，不重复追加用户气泡，后续模型上下文排除草稿。
- 在模型函数尚未返回时读取SQLite，确认generating请求和第一版已展示草稿已经落盘，而非仅写内存。
- 后台复盘修订后失败：ReviewJob快照保留被拒草稿。
- 三种“更难/简单”表述命中操作入口却不虚构难度；“再来解释一下上一局”不重开。
- 浏览器8502独立数据库、假模型固定延迟和末尾注入失败：实际先看到增量，再看到失败状态正文还在，再刷新看到同一草稿。截图stream-failure-retained-preview.png、stream-failure-restored-preview.png。这是失败生命周期验证，不冒充真实模型语义评估。

第一次完整回归发现移除rerun后离线分支的工具凭据未立即显示（192通过/1失败），修复实际渲染逻辑；没有删除该断言。最终完整测试结果见BUILD_LOG第35节。

## 尚未解决或不能保证的部分

没有用“保留草稿”掩盖语义错误。模型仍可能提出错误分析，程序检查也不是全面语义证明。此次主要让路由、展示状态、持久记录和失败反馈一致。

进程突然退出、系统崩溃或页面中断，最后一次0.5秒检查点之后的增量可能丢失，记录可能停留generating；页面会标为未完成，不自动重发付费请求。没有浏览器持久缓存、生产级任务队列、多窗口草稿写入仲裁或跨进程流式恢复。SQLite保存异常等未捕获基础设施错误不在本次模拟覆盖范围。提前离开旧局的后台复盘收集限制仍见ASYNC_REVIEW.md。已保存旧失败消息不批量篡改成“修好后”的样子。
