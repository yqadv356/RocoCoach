# 流式正文为什么消失 怎样保留下来

更新于2026年10月31日。这个问题涉及显示、校验和保存三步，不能只靠打开stream解决。

## 当时发生了什么

玩家已经看见生成中的文字，但完整响应回来后，系统会再检查格式、引用和当前场景。检查没通过时，旧逻辑清掉草稿，写一条固定观察，再重绘页面。结果就是：等了很久，想看的内容反而不见了。

另两条路径也造成过类似现象：显示层误把英文昵称当未翻译术语，替换整段文字；后台复盘完成后在不同页面位置交接，原占位被撤掉。它们外观相似，根因不同，必须分别验证。

早期测试还明确要求失败时清空草稿。测试通过并不能证明满足了用户需求，这个验收规则也一起改了。

## 现在怎样处理

每次请求先保存一个request_id，并关联同一条消息。生成、成功和失败都更新这条消息，不再临时显示一份、最后另存一份。

| 阶段 | 玩家看到什么 | 数据怎样处理 |
| --- | --- | --- |
| 生成中 | 已经收到的正文和当前进度 | 约每半秒保存一次实际可见草稿 |
| 检查或修正中 | 保留可见版本，说明还在核对 | 记录修订版本，不把它当正式答案 |
| 成功 | 原位置显示完成内容 | 保存正式回答，再进入正常上下文 |
| 失败 | 原位置保留草稿，标明未完成或未通过核对 | 保存失败和草稿，排除正常事实记忆 |
| 刷新 | 恢复已保存回答或可查看草稿 | 不自动重发付费请求 |

只保存实际显示过的正文，不展示隐藏思考，也不通过诊断字段把本来被拦住的内容重新泄露出来。最多保存八版、每版12000字符；“保留草稿”不等于承认草稿正确。

普通聊天成功和失败都在原位置收尾，不强制整页重绘。开新局确实需要切换页面状态时，由操作事务清理待完成占位并保存一次反馈，避免重复气泡。

## 为什么失败草稿不能继续喂给模型

它可能正是因为宠物、引用或分析不一致而失败。如果下一轮把它当事实，模型会沿着错误继续说。保留给玩家查看和排查，与作为正式上下文使用，是两件事。

已经结算的对局也不会因回答失败而回滚。重试复盘只是重新生成解释，不再执行一次出招。

## 怎样验证

测试分别覆盖断流、显示后末尾失败、多次修订后失败、生成尚未结束时草稿已写入数据库，以及刷新恢复；还检查失败内容没有进入正常聊天和学习事件。

浏览器用独立数据库和模拟模型延迟验证“先看到增量、失败后仍在、刷新后仍可查”。这证明展示链路，不是对模型理解能力的评测。原始阶段记录已归档，当前程序成绩见[VALIDATION](VALIDATION.md)。

## 还会丢什么

检查点不是逐字写入。进程突然退出时，最后半秒左右尚未保存的内容可能丢失，消息也可能停在未完成状态。当前没有跨进程断点续传、浏览器持久缓存或多窗口写入仲裁。
